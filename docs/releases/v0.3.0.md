# RanD v0.3.0

## Highlights

- Parallel-safe JSON state updates with owned lock metadata and stale recovery.
- Atomic run publication through staging directories and SHA-256 manifests.
- Artifact contract 2.0 using JSON Schema Draft 2020-12.
- Audited GitHub Issue delivery through tracker-bridge v1.1.0.
- Explicit dry-run, shadow, and doubly-confirmed live delivery modes.

## Compatibility changes

CLI status is now reflected in the process exit code:

| Report status | Exit code |
|---|---:|
| ok | 0 |
| failed | 1 |
| degraded | 2 |

This applies to run-once, heartbeat, and run-schedule. Schedule execution uses
the worst child status. validate-artifact returns 0 for valid schema 2.0, 2 for
readable legacy schema 1.0 with warnings, and 1 for contract violations.

New artifacts use schema 2.0. Schema 1.0 remains readable but cannot be sent
through live delivery. Existing artifacts are not converted automatically.

Subagent commands now use JSON arrays in RAND_INSIGHT_SUBAGENT_ARGV and
RAND_GATE_SUBAGENT_ARGV with shell disabled. Legacy SUBAGENT_CMD values are
accepted only when RAND_ALLOW_SHELL_SUBAGENT=1 and force a degraded warning.

## Live delivery safety

Live GitHub delivery requires --delivery-mode live plus --confirm-live, or
RAND_CONFIRM_LIVE_DELIVERY=1. Dry-run and shadow modes do not call tracker APIs.
Connection URL, repository key, and credential reference are loaded from
tracker-bridge; RanD stores only delivery observations and typed references.

Jira live creation, SQLite migration for RanD state, and bulk conversion of
legacy artifacts are not included.
